This file is the dated, honest snapshot of what is actually true in this
repository — not what it aspires to be. It is the third of the
README / EXPLAINME / AFFIRMATION trio. Update it whenever the real state moves.

== What is true today

* The repository was instantiated from the RSR template (`rsr-template-repo`)
  on 2026-07-02 via `just init`, then given its real identity by hand
  (6a2 metadata, README, EXPLAINME, contractiles).
* The formally-typed ABI/FFI seam is *real code and builds*:
  `src/interface/ffi/` (Zig) exports `stateful_artefacts_*` C symbols;
  `src/interface/Abi/` (Idris2) binds them with a shared 5-value `Result`
  canon (ADR-003). Zig unit and integration tests pass locally under
  Zig 0.15.2.
* `just validate`, `bash scripts/validate-template.sh .`, `just verify-template`,
  and `bash tests/aspect_tests.sh` pass locally.
* A *v0 artefact-state-record* slice now exists and is exercised end-to-end:
  the record + its two state machines (forward-only `phase`, monotonic
  `verification`) are implemented in `src/core/record.zig`, exposed over the C
  ABI (`stateful_artefacts_record_*`, mirrored in the hand-maintained header and
  bound in `Abi/Record.idr`), and covered by Zig unit + integration tests
  (16 total pass) plus a C smoke test linked against the static lib. The record
  is *PROVISIONAL* and *additive-only* (docs/spec/ARTEFACT-STATE-RECORD.adoc).

== What is NOT true yet (do not overstate)

* *The reposystem domain content is still missing.* `src/contracts`,
  `src/errors`, and most of `src/definitions` remain structured scaffolds; the
  reposystem-specific behaviour (graph exports, scenario state, VeriSimDB) is
  pending a content re-transfer from `hyperpolymath/reposystem` (the original
  split lost it). The v0 artefact-state-record above is this repo's *own*
  deliverable, not the reposystem content. See the re-transfer checklist in
  `README.adoc`.
* The project definition in `STATE.a2ml` / `README.adoc` is marked
  *PROVISIONAL* and may be refined once the re-transfer clarifies the scope.
* *Formal proofs are authored but not machine-checked here.* The v0 lifecycle
  proofs (`src/interface/Abi/Record.idr` typed transitions; the fixed
  `Abi/Foreign.idr`; `verification/proofs/tlaplus/ArtefactLifecycle.tla`) were
  written but *not* run: no idris2/Agda/Coq/Lean/TLC toolchain is present, and
  the idris-lang GitHub source is blocked in this environment. They run via
  `just typecheck-abi` / `just proof-check-idris2` / `tlc` where those
  toolchains are installable. *No idris2 CI step was added* because a
  SHA-pinned idris2 setup action could not be resolved here without re-breaking
  the workflow-security linter — recommended follow-up: add
  `idris-community/setup-idris` (SHA-pinned) + `just typecheck-abi` to CI.
* The `k9.ncl` self-validating contractiles and Nickel policies were *not*
  verified locally (no `nickel` / `k9-svc` available).

== Open questions for the maintainer

* *Licence discrepancy.* This repo is normalised to MPL-2.0 (code) +
  CC-BY-SA-4.0 (docs), but `hyperpolymath/reposystem` — the extraction parent —
  declares *PMPL-1.0*. This must be reconciled before the re-transfer lands.
* *Rust CI without Rust.* `.github/workflows/rust-ci.yml` and
  `.machine_readable/compliance/rust/deny.toml` are retained on the expectation
  that the reposystem content is Rust-core; if the domain turns out not to be
  Rust, delete both.
* *Provisional external registrations.* The Groove port (`8471`), the clade
  prefix (`gv-stateful-artefacts`), and the OpenSSF Best Practices ID are
  placeholders pending registration in the (currently unreachable) `standards`
  and `gv-clade-index` repos.
