State-carrying artefact layer of the Reposystem/OPSM stack: schemas and tooling for artefacts that carry machine-readable state (identity, provenance, lifecycle, verification) across the hyperpolymath estate.

== What this is

[NOTE]
====
*PROVISIONAL definition — refine on content re-transfer.* This repository was
split out of https://github.com/hyperpolymath/reposystem[reposystem] (the
railway-yard estate-coordination tool), but the original content transfer
failed: only the RSR template shell arrived. The repo has since been properly
instantiated; the domain content is being re-transferred from reposystem
(see <<Re-transfer status>>).
====

Reposystem treats a ~300-repo estate as a railway yard: repos are yards, edges
are tracks, provider choices are switch points, and everything it knows is
exported as artefacts — graph exports, scenario states, estate metadata,
VeriSimDB feed records. *Stateful Artefacts* is the layer those artefacts pass
through: one canonical, machine-readable *state record* (identity, provenance,
lifecycle phase, verification status) that any artefact can carry, plus the
tooling to read, write, and validate those records from any language via a
formally-typed C ABI (Idris2-proven layout, Zig implementation).

A *v0* of that record now exists — the schema
(link:docs/spec/ARTEFACT-STATE-RECORD.adoc[ARTEFACT-STATE-RECORD]), a Zig core
(`src/core/record.zig`) with a typed lifecycle (forward-only phase, monotonic
verification) exposed over the `stateful_artefacts_record_*` C ABI, and lifecycle
proofs (Idris2 `Abi/Record.idr` + TLA+ `ArtefactLifecycle.tla`). It is
PROVISIONAL and additive-only; the reposystem-specific domain content still
arrives via the <<Re-transfer status,re-transfer>>.

== What you get

* *Machine-readable metadata* (`.machine_readable/6a2/`) — `STATE`, `META`,
  `ECOSYSTEM`, `PLAYBOOK`, `AGENTIC`, `NEUROSYM`, `CLADE`, and `anchors/ANCHOR`,
  in a2ml, so tools and agents can read the project's state and boundaries.
* *AI gatekeeper protocol* — `0-AI-MANIFEST.a2ml` is the universal entry point that
  tells an AI agent how to work in this repo before it touches anything.
* *Typed ABI/FFI seam* — `src/interface/Abi/` (Idris2 type + layout proofs) over
  `src/interface/ffi/` (Zig implementation), with a hand-maintained C header in
  `src/interface/generated/abi/`.
* *CI/CD* — GitHub Actions for quality, security (CodeQL, Scorecard, secret
  scanning), multi-forge mirroring, and RSR anti-pattern enforcement.
* *Supply-chain & reproducibility* — container layering (stapeln), Nix/Guix shells,
  SBOM, and signing hooks.
* *Governance* — `GOVERNANCE.adoc`, `MAINTAINERS.adoc`, `.github/` community health
  files, and a release `AUDIT.adoc` gate.

re-extracted by the maintainer (that repo is not reachable from CI here):

1. Decide the slice — candidates: `src/verisimdb.rs`, the exporter/state parts

   reposystem, then merge into this repo with `--allow-unrelated-histories`.
3. Land code in `src/core` / `src/definitions` / `src/bridges`, specs in
   `docs/`; update `META.a2ml` languages and `STATE.a2ml` completion; delete
