== What this is

[NOTE]
====
*PROVISIONAL definition — refine on content re-transfer.* This repository was
split out of https://github.com/hyperpolymath/reposystem[reposystem] (the
railway-yard estate-coordination tool), but the original content transfer
failed: only the RSR template shell arrived. The repo has since been properly
instantiated; the domain content is being re-transferred from reposystem
(see <<Re-transfer status>>).
====

Reposystem treats a ~300-repo estate as a railway yard: repos are yards, edges
are tracks, and provider choices are switch points. It exports graph,
scenario, and estate metadata artefacts. *Stateful Artefacts* is the layer
those artefacts should pass through: one canonical, machine-readable *state
record* (identity, provenance, lifecycle phase, verification status) that any
artefact can carry, plus tooling to read, write, and validate those records
from any language via a formally-typed C ABI (Idris2 layout model, Zig
implementation). VeriSimDB persistence remains outside this repository's
current scope; the local provisional exporter is not a database sink.

A *v0* of that record now exists — the schema
(link:docs/spec/ARTEFACT-STATE-RECORD.adoc[ARTEFACT-STATE-RECORD]), a Zig core
(`src/core/record.zig`) with a typed lifecycle (forward-only phase, monotonic
verification) exposed over the `stateful_artefacts_record_*` C ABI, and
lifecycle proof sources (Idris2 `Abi/Record.idr` + TLA+
`ArtefactLifecycle.tla`; not yet machine-checked by CI). It is PROVISIONAL and
additive-only; the reposystem-specific domain content still
arrives via the <<Re-transfer status,re-transfer>>.

== What you get

* *Machine-readable metadata* (`.machine_readable/descriptiles/`) — `STATE`, `META`,
  `ECOSYSTEM`, `PLAYBOOK`, `AGENTIC`, `NEUROSYM`, `CLADE`, and `anchors/ANCHOR`,
  in a2ml, so tools and agents can read the project's state and boundaries.
* *AI gatekeeper protocol* — `0-AI-MANIFEST.a2ml` is the universal entry point that
  tells an AI agent how to work in this repo before it touches anything.
* *Typed ABI/FFI seam* — `src/interface/Abi/` (Idris2 ABI types and proof
  sources) over `src/interface/ffi/` (Zig implementation), with a
  hand-maintained C header in `src/interface/generated/abi/`. The proof sources
  are not yet machine-checked in CI.
* *CI/CD* — GitHub Actions for quality, security (CodeQL, Scorecard, secret
  scanning), multi-forge mirroring, and RSR anti-pattern enforcement.
* *Supply-chain & reproducibility* — container layering (stapeln), Nix/Guix shells,
  SBOM, and signing hooks.
* *Governance* — `GOVERNANCE.adoc`, `MAINTAINERS.adoc`, `.github/` community health
  files, and a release `AUDIT.adoc` gate.

== Re-transfer status

The domain content still lives in `hyperpolymath/reposystem` and must be
re-extracted by the maintainer (that repo is not reachable from CI here). The
full harness — extraction, a reconciliation map onto the v0 record, the
remaining decisions (core language, ABI canon, licence), the current
VeriSimDB-local-only boundary, and verification gates — is in link:docs/RE-TRANSFER-RUNBOOK.adoc[the re-transfer
runbook], driven by `scripts/retransfer-from-reposystem.sh` (dry-run by default).

In brief:

1. Decide the slice — candidates: exporter/state parts of `src/graph.rs`,
   scenario state, and `spec/DATA-MODEL.adoc`. The current scope keeps
   `src/verisimdb.rs`'s persistence client in Reposystem; do not transfer it as
   an adapter to VeriSimDB's Octad API.
2. Extract with history via the script (`git filter-repo`), then merge with
   `--allow-unrelated-histories`.
3. Land + reconcile onto the v0 artefact-state-record (`src/core` /
   `src/definitions` / `src/bridges`, specs in `docs/`); do not fork the state
   model; update `META.a2ml` / `STATE.a2ml`. Remove only markers whose
   assumptions are resolved; retain the v0/local-serializer PROVISIONAL
   markers (the current scope has no VeriSimDB mapping or sink).
4. Resolve the licence question: reposystem declares PMPL-1.0; this repo is
   normalised to MPL-2.0 (code) + CC-BY-SA-4.0 (docs).
