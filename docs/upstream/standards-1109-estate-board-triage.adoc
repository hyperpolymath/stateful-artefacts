Three findings, in order of importance:

. *The caller job id is half the required context name.* A caller using job id `secret-scan`
  emits `secret-scan / gitleaks` and can never satisfy a `scan / gitleaks` requirement — a
  phantom context, which is exactly the freeze the reusable's own header warns about
  ("caller job ids are FROZEN until this derivation replaces every typed ruleset"). Three repos
  are in this state: `awesome-zig`, `cargo-zigbuild`, `explore`.
. *The applier's refusals are window-driven, not current.* `--require-green N` refuses if any of
  the last `N` runs cannot be read; the zero-job runs it trips over are *older* pins still
  inside the window, while the latest run emits 2–3 jobs in 9 of 10 repos. Converging the pins
  and letting clean runs accumulate is what unblocks a stricter derivation.
. *A rejected reusable call produces no check run at all.* The reusable's header records the
  diagnosis rule: `gh pr checks` shows nothing and the annotations endpoint 404s, so diagnose
  with `gh run list --json conclusion`, never by the absence of a red tick.

An older pin (`892497fe` in `ambientops`) shows the same failure class as `bd0df9ea`. Both are
real commits in `standards`, so this is pin *staleness*, not a dead ref — the "DEAD-REF" class
`apply-workflow-pins-remote.sh` describes.

#    WITHOUT --require-green 1 to require the full derived context set.

*Do not require `ambientops`'s red pair yet.* `scan / gitleaks` and
`rust-ci / Cargo check + clippy + fmt` are genuinely failing on `main` there — not failing to
start. Requiring them now blocks every future PR behind a pre-existing red.

Caveat from the estate's own notes (`config/rulesets/README.adoc`): the estate's fine-grained PAT
was measured returning *404 on `PUT`/`PATCH`* of repo-level rulesets while `POST` is accepted. If
step 2 fails that way it is the documented token limitation, not a script defect; the escape
hatch is the create path used in step 3, which `POST`s the canon checks-only body instead of
filling an existing ruleset.
