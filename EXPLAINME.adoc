== What the project is

Stateful Artefacts is the state-record and ABI/FFI layer of the Reposystem/OPSM
stack. Reposystem (https://github.com/hyperpolymath/reposystem) coordinates a
~300-repo estate as a railway yard and emits graph exports, scenario states,
and estate metadata. Reposystem still owns its legacy VeriSimDB snapshot client;
this repository does not own a database or a network sink. Stateful Artefacts
defines the canonical *state record* those artefacts should carry (identity,
provenance, lifecycle phase, verification status) and cross-language tooling to
read, write, and validate records.

Caveat:

* The original split out of reposystem lost additional domain content. This
  repository's v0 state-record core and ABI/FFI seam exist, but the broader
  graph/scenario domain model is still under maintainer review for re-transfer
  (see `README.adoc`, "Re-transfer status", and `STATE.a2ml` blockers).

== Architecture: the ABI seam

Claim:
The record format has one binary contract shared by every language.

How this is implemented:

* `src/interface/Abi/Types.idr` — Idris2 types with a `DecEq`-checked `Result`
  enum and a non-null `Handle` invariant (`So (ptr /= 0)`), `%default total`.
* `src/interface/Abi/Layout.idr` — C-ABI layout compliance as constructive
  proofs (`Divides`, `CABICompliant`).
* `src/interface/Abi/Foreign.idr` — `%foreign` bindings to the
  `stateful_artefacts_*` C symbols.
* `src/interface/ffi/src/main.zig` — the Zig implementation exporting those
  symbols; built by `src/interface/ffi/build.zig` as static + shared
  `libstateful_artefacts`.
* `src/interface/generated/abi/stateful_artefacts.h` — hand-maintained C
  header, the contract for C consumers.

Caveat:

* The Zig implementation and its tests exist; this workspace has no `zig` or
  `just` executable, so they could not be rerun for the 2026-10-04 review.
  Idris2/TLA+ proof sources are authored, but are not currently machine-checked
  by this repository's CI. Do not describe them as verified until a proof gate
  runs and its result is recorded.

== Central Session Protocol Authority

Claim:
Session protocols are centrally maintained and not duplicated here.

How this is implemented:

* The local dispatcher (`session/dispatch.sh`) maps canonical commands to central
  protocol paths in `standards/session-management-standards`.
* Local files (`session/custom-checks.k9`, `session/local-hooks.sh`,
  `coordination.k9`) are integration-only.

Caveat:

* If `SESSION_STANDARDS_DIR` is unset and no adjacent standards checkout exists,
  the dispatcher records the command but cannot resolve central checklist paths.

== Canonical Command Surface

Claim:
Bindings align to one canonical command model.

How this is implemented:

* `Justfile` provides thin aliases (`intake-repo`, `checkpoint-change`,
  `verify-maintenance`, `verify-substantial`, `verify-release`, `close-planned`,
  `close-urgent`, `recover-repo`, `handover-*`).
* Every alias calls `session/dispatch.sh` with canonical verb-object pairs.

Caveat:

* Recipes are wrappers only. They do not replace protocol content from
  the central standards repo.

== Runtime State Is Local

Claim:
Session state is per-repository runtime output, not standards text.

How this is implemented:

* `session/dispatch.sh` writes command and continuity-core capture stubs to
  `.session/LAST-CANONICAL-COMMAND.md` in the target repository path.

Caveat:

* Runtime files are intentionally lightweight and require human/agent completion.

== Honest state

* Instantiated from `rsr-template-repo` on 2026-07-02 (`just init` + manual
  identity pass).
* `src/core/record.zig` and `src/definitions/artefact-state-record.a2ml`
  implement the provisional v0 state record. `src/bridges/verisimdb-feed.sh`
  writes a tested local-only JSON representation; no mapping to the current
  upstream Octad API/model or any agreed modality profile exists here, and there
  is no network sink. Other domain components (including `src/contracts/` and
  `src/errors/`) still await an explicit re-transfer scope.
* `verification/proofs/` includes authored Idris2/TLA+ lifecycle proof sources
  plus scaffolding for other provers. The proof sources are not currently
  machine-checked by this repository's CI.
* See `AFFIRMATION.adoc` for the dated snapshot and open questions (including
  the PMPL-1.0 vs MPL-2.0 licence discrepancy with reposystem).
